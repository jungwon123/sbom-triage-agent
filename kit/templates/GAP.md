## 현재 구현 요약 (2026-11-18 기준)

| 단계 | 되는 것 | 안 되는 것 |
|---|---|---|
| ① SBOM | Syft, package-lock.json, pom.xml(직접 의존성), CycloneDX와 SPDX JSON 파일 | yarn, pnpm, Gradle lockfile 직접 파싱 |
| ②③ 스캔과 보강 | OSV(npm, Maven), EPSS, KEV, 수정 버전, import 검색(JS/TS, Java/Kotlin) | PyPI, Go 등 다른 생태계 |
| ④ 규칙 점수 | 25/25/50, 조치 비용, 하향 보류 대상 | |
| ⑤ 에이전트 | Anthropic, OpenAI, replay 어댑터, 계약 검사, 규칙 대체 | 실호출 검증 여부는 HANDOFF 참고 |
| ⑥ 검증 | npm 샌드박스, 기준선 비교, 재스캔, 재시도 | Maven 등 다른 생태계의 샌드박스 |
| ⑦ 화면 | 요약, 버킷 목록, 상세, 정렬 토글, 검증 결과 | 승인 뒤 PR 생성 |
| 평가 | 세 방식 일치율, NOW 누락 | 정답 라벨이 있어야 수치가 나온다 |

## 재사용할 수 있는 구조 (과제가 달라져도)
- 규칙이 점수를 내고 AI는 제한된 범위만 조정한다 (`AgentVerdict`, 계약 검사, 규칙 대체)
- 읽기 전용 도구, 코드가 만드는 명령, 일회용 샌드박스
- 이벤트 기록과 오프라인 리플레이
