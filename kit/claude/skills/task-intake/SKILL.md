# task-intake — 과제 정리와 차이 분석

코드를 고치지 않는다. 과제 문서에 없는 요구를 지어내지 않는다.

## 1. 과제 정리 (TASK.md)
1. `data/`에서 과제 설명 문서를 찾아 끝까지 읽는다. 자료 파일은 열지 않고 `out/profile.md`만 본다.
2. 다음을 과제 문서의 **문장 위치**(파일, 쪽 또는 절)와 함께 적는다.
   - 만들어야 하는 것, 필수 요구, 가산 요소
   - 평가 기준과 배점
   - 제공 도구와 자료, 사용 제한(외부 API, 외부 전송, 네트워크)
   - 제출물과 마감, 시연 방식과 시간
3. 문서에 없어서 모르는 것은 "미확인"으로 두고 운영진에게 물을 질문으로 적는다. 추측으로 채우지 않는다.

## 2. 차이 분석 (GAP.md)
요구마다 현재 구현이 어디까지 되는지 **코드와 테스트로** 확인한다.

| 볼 곳 | 확인 방법 |
|---|---|
| 입력 형식 | `out/profile.md`의 "지원 / 미지원" 표시, `backend/triage/sbom.py` |
| 판단 | `score.py`, `agent/run.py`의 계약 검사 |
| 검증 | `verify/`, 생태계별 지원 여부 |
| 화면 | `web/src` |
| 평가 | `eval.py`, 정답 라벨 유무 |

항목마다: 요구 / 현재 상태(됨, 부분, 없음) / 근거(파일, 테스트 이름) / 필요한 작업 / 예상 시간 / 깨질 수 있는 것.

## 3. 재사용 판단
과제가 지원서 주제와 다르면 재사용할 수 있는 부분을 따로 적는다: 규칙과 AI의 경계(`AgentVerdict`), 계약 검사와 규칙 대체, 읽기 전용 도구, 코드가 만드는 명령, 샌드박스, 이벤트 기록과 리플레이.
