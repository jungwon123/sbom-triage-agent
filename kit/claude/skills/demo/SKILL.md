# demo — 시나리오, 대본, 리플레이

화면에 보이는 모든 수치는 저장된 실행(`out/<run>/`)에서 온다. 대본의 숫자를 손으로 쓰지 않는다.

## 1. 시연용 실행 고정
1. 시연에 쓸 실행을 고른다. 스캔, 에이전트, 검증이 모두 끝난 실행이어야 한다(`meta.json`의 `stages`).
2. `python3 kit/scripts/evidence.py`로 수치를 모은다.
3. 오프라인 확인: 네트워크를 끄고 `DEMO_MODE=replay uv run uvicorn triage.api:app` → 브라우저에서 `/?run=<id>`. 화면은 저장된 결과만 읽으므로 그대로 떠야 한다.

## 2. 시나리오 (SCENARIOS.md)
권장 구성. 과제가 다른 장면을 요구하면 그쪽을 따른다.
1. **압축**: 전체 취약점 수 → NOW 건수. CVSS 순 정렬과 우선순위 정렬을 토글로 비교한다.
2. **대비 사례 A**: CVSS는 높지만 코드에서 쓰지 않아 내려간 항목. 근거와 사용 위치를 보여 준다.
3. **대비 사례 B**: CVSS는 중간이지만 운영 코드에서 써서 올라간 항목, 또는 안전장치로 하향이 보류된 항목.
4. **검증**: NOW 항목의 샌드박스 결과. 단계별 결과, 판정, 실행된 테스트 수.
5. **한계 공개**: 틀린 사례 1건 또는 `inconclusive` 1건과 그 이유.

장면마다: 보여 줄 항목(finding id) / 화면에서 보여야 하는 값 / 그 값의 출처(evidence의 어느 줄) / 대응 테스트 이름.

## 3. 대본 (DEMO_SCRIPT.md)
- 장면당 한 문장. 설계 이유는 발표 자료와 QA.md에 둔다.
- 화면 문구와 버튼 이름은 `web/src`의 실제 문자열과 같아야 한다. `grep -rn "<문구>" web/src`로 확인한다.
- 전체 길이를 재고 제한 시간의 80% 안에 들어오게 한다.

## 4. 리허설 전 확인
- `bash kit/scripts/check.sh` 통과
- 네트워크와 Docker를 끈 상태에서 처음부터 끝까지 한 번
- 브라우저 배율, 알림 끄기, 시연용 run id를 주소창에 미리 넣어 두기
