# agent-eval — 일치율 측정

수치를 좋게 만들려고 정답이나 사례를 고르지 않는다. 틀린 사례는 지우지 않고 기록한다.

## 절차
1. 정답을 확인한다: `fixtures/golden.yaml`, `fixtures/golden-sheet.csv`, 또는 현장 제공 라벨. 라벨이 0건이면 멈추고 사람에게 라벨링을 요청한다. **에이전트가 정답을 대신 매기지 않는다.** `out/poc/golden-key.json`은 열지 않는다.
2. `uv run python -m triage eval out/<run> [--golden <파일>]` → `out/<run>/eval.json`
3. 표로 보고한다.

   | 방식 | 일치율 | NOW 누락 | 틀린 건수 |
   |---|---|---|---|
   | CVSS 정렬 | | | |
   | 규칙 단독 | | | |
   | 규칙 + AI | | | |

   대상 건수와 그중 AI가 실제로 판단한 건수(`agent_judged`)를 같이 적는다. AI가 판단한 건이 0이면 "규칙+AI" 줄은 규칙 단독과 같다는 점을 밝힌다.
4. 틀린 사례를 원인별로 나눈다: 규칙 가중치 / 코드 사용 여부 오판 / 데이터 누락 / 안전장치로 하향 보류 / 정답 자체가 애매함.
5. `agent_log.jsonl`에서 계약 위반과 규칙 대체 건수를 센다. 대체가 많으면 일치율은 AI의 성능이 아니다.

## 고치는 순서
- NOW 누락이 먼저다. 한 건이라도 있으면 원인과 사례를 공개한다.
- 규칙(가중치, 임계값)을 바꾸려면 근거 사례를 들어 선택지로 내고 멈춘다. 바꾸면 `tests/test_score.py`의 경계값도 같이 바꾼다.
- 프롬프트를 바꿨으면 같은 정답으로 다시 측정하고 이전 수치와 나란히 적는다. 표본이 작으면(20건 이하) 1~2건 차이는 개선이라고 말하지 않는다.
