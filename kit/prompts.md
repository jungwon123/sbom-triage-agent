# prompts — 단계별 프롬프트 (사람용)

그대로 붙여 넣어도 되지만 `<>` 자리는 **내 판단**으로 채운다.
좋은 지시의 다섯 요소: **목적** / **근거 파일** / **지켜야 할 제약** / **완료 기준** / **검증 방법**.
Codex에서는 "○○ 스킬" 대신 "`kit/claude/skills/○○/SKILL.md`를 읽고 그 절차대로"라고 쓴다.

---

## P0. 시작
```
kit/START.md 읽고 그대로 해.
```

## P1. 범위 결정
```
docs/finals/GAP.md의 차이 목록을 필수, 가산점, 무관으로 나누고 항목마다 예상 작업 시간과 깨질 위험이 있는 테스트를 붙여 줘.
마감은 11/25 13:00이고 첫날 밤에 동결한다. 추천 범위 2안(안전, 공격)을 보여 주고 멈춰.
```
→ 고른 뒤:
```
<안전/공격>안으로 간다. 뺄 것: <항목>. 이유: <한 줄>. GAP.md에 결정을 표시하고 DECISIONS.md에 남겨.
```

## P2. 자료 점검
```
data-check 스킬로 data/ 를 점검해 docs/finals/DATA_NOTES.md를 채워 줘.
파일마다 의미, 키, 형식, 현재 파이프라인의 어느 단계 입력인지, 한계를 적어.
정답 라벨이나 평가용 자료가 있으면 따로 표시하고, 판단에 필요한데 없는 정보는 "필요 정보 / 왜 / 메우는 방법"으로 보여 주고 멈춰.
```

## P3. 입력 맞추기
```
adapt-input 스킬로 <자료 종류>를 파이프라인 입력으로 연결해.
먼저 현장 자료의 실제 사례 2~3건으로 실패하는 테스트를 쓰고 계획 3줄만 보고해.
제약: models.py의 Component 또는 Finding에 맞출 것, 외부 호출은 cache.py 경유, 기존 테스트 유지.
완료 기준: `uv run python -m triage scan <현장 자료>`가 성공하고 coverage가 출력됨.
```

## P4. LLM 연결과 판단
```
uv run python -m triage doctor --llm 으로 연결을 확인하고, 현장 자료의 최신 실행에 `triage agent out/<run> --limit 5`를 돌려.
agent_log.jsonl에서 도구 호출 횟수, 계약 위반, 오류를 요약하고 근거 문장 5건을 그대로 보여 줘.
위반이 있으면 프롬프트를 고치지 말고 먼저 원인을 분류해서 보고해.
```
→ 확인 뒤:
```
<전체/상위 N건>으로 다시 돌려. 비용 상한은 --limit <N>.
```

## P5. 일치율 측정
```
agent-eval 스킬로 일치율을 측정해. 정답은 <fixtures/golden-sheet.csv / 현장 제공 라벨>.
CVSS 정렬, 규칙 단독, 규칙+AI 세 가지를 같은 표로 보여 주고 NOW 누락과 틀린 사례를 원인별로 나눠.
규칙을 고치자는 제안은 근거 사례와 함께 선택지로 내고 멈춰.
```

## P6. 검증
```
verify-run 스킬로 NOW 항목을 샌드박스에서 검증해. 설정 명령: <"npx prisma generate" / 없음>.
판정별 건수, verified 중 실제 테스트가 실행된 건수, failed의 원인을 표로 보여 줘.
대상 레포가 바뀌지 않았는지 git status로 확인해.
```

## P7. 과제별 추가 요구
```
TASK.md의 <요구 번호>를 구현할 계획 3줄(바꿀 파일 / 방법과 버린 대안 / 테스트 케이스)만 보고해.
제약: CLAUDE.md 4장 절대 규칙, 스키마를 바꾸면 web 타입도 같은 커밋에서.
```

## P8. 화면과 시나리오
```
demo 스킬로 docs/finals/SCENARIOS.md와 DEMO_SCRIPT.md를 채워. 시연에 쓸 run은 <run id>.
장면마다 화면에서 보여야 하는 수치를 out/evidence.md에서 가져오고, 대본의 화면 문구가 web/src 의 실제 문구와 같은지 확인해.
```

## P9. 중간 점검과 동결
```
reviewer 서브에이전트로 review 스킬 모드 B를 돌려. 지적 목록만 받아서 보여 줘.
```
→ 지적마다:
```
<n>번 수용, <m>번 거절(이유: <한 줄>). 수용한 것만 고치고 DECISIONS에 남겨. 끝나면 handoff 스킬로 HANDOFF를 갱신하고 동결 커밋해.
```

## P10. 발표와 제출
```
python3 kit/scripts/evidence.py 를 실행하고, 발표 자료 초안(<파일>)의 수치를 out/evidence.md와 한 줄씩 대조해 불일치만 보여 줘.
그다음 review 스킬 모드 C로 제출 전 점검을 하고 docs/finals/SUBMIT_CHECKLIST.md를 채워.
```
