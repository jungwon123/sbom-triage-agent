# 키워드 사전

프론트엔드 개발자 기준으로 발표와 질의응답에 필요한 개념을 정리했습니다. 제품 코드(`backend/`, `web/`)는 아직 없고, 운영 설계(PostgreSQL, 작업 큐, 워커)는 D32와 PoC까지만 있습니다. LLM 에이전트는 아직 실행하지 않았고, 일치율과 NOW 누락은 라벨링 전이라 미측정입니다.

## 가장 먼저 익힐 10개 (★)

SBOM, EPSS, reachability, 버킷, 하이브리드 판단과 ±1 제약, NOW 누락, 프롬프트 인젝션, 일회용 컨테이너, 기준선 비교, 검증 강도.

## 1. 공급망 보안

| 키워드 | 뜻 | 우리 프로젝트에서 |
|---|---|---|
| ★ SBOM / CycloneDX | SBOM은 소프트웨어의 부품(패키지) 명세서이고, CycloneDX는 이를 쓰는 표준 형식입니다. `package.json`을 표준 양식으로 풀어 쓴 목록에 가깝습니다. | ①단계가 `sbom.cdx.json`을 만들고 스캔은 이것만 입력으로 씁니다(D20, F2-5). |
| Syft | 코드 폴더를 읽어 SBOM을 만드는 오픈소스 도구입니다. | `sbom.py`가 호출하고 실패하면 lockfile을 파싱합니다(F2-2). PoC는 Syft 미설치로 lockfile 파싱을 썼습니다. |
| OSV | 오픈소스 취약점 공개 DB와 API입니다. | `querybatch`로 ID를 받고 상세는 따로 조회합니다(F3-1). |
| CVE / GHSA | 취약점 번호입니다. CVE는 범용, GHSA는 GitHub 어드바이저리 번호입니다. | npm은 GHSA가 기본이고 CVE가 없을 수 있습니다. EPSS는 CVE에만 있어 없으면 `None`입니다. |
| CVSS | 이론상 최악일 때의 심각도(0~10)입니다. 실제 악용이나 사용 여부는 반영하지 않습니다. | `severity = CVSS/10 × 25`(F5). CVSS 정렬 비교 토글이 핵심 장면입니다(F7-4). |
| ★ EPSS | 실제 공격에 쓰일 확률을 예측한 점수입니다. FIRST가 제공합니다. | `exploit` 25점의 입력입니다(F4-1). PoC에서 581건 중 556건(95.7%) 확보. |
| KEV | CISA가 실제 악용을 확인한 취약점 목록입니다. | `exploit=1.0`이 되고 AI 하향이 금지됩니다(F6-9). PoC의 npm 항목에서는 0건이었습니다. |
| transitive dependency | 설치한 패키지가 끌고 온 간접 의존성입니다. 직접 의존성은 `direct`입니다. | `path_w`가 direct 1.0, transitive 0.7입니다. 간접 의존성은 도달성을 `unknown`으로 둡니다. |
| ★ reachability(도달성) | 취약한 패키지를 우리 코드가 실제로 쓰는지 따지는 개념입니다. | `used_symbol` / `imported_only` / `unused` / `unknown`. 1차 import 검색(F4-4), 2차 에이전트(F6-1). 변이 시험 18/36은 어려운 유형을 절반 넣은 값이라 실제 정확도가 아닙니다. |

**예상 질문:** CVSS가 높으면 먼저 고쳐야 하지 않나요?
**답:** CVSS는 이론상 최악의 크기일 뿐이라, 악용 확률(EPSS)과 실제 사용 여부(reachability)를 함께 봅니다.

## 2. 판단 설계

| 키워드 | 뜻 | 우리 프로젝트에서 |
|---|---|---|
| 규칙 점수(risk, effort) | 사람이 정한 수식의 점수입니다. 같은 입력이면 항상 같은 결과가 나옵니다. | `score.py` 순수 함수. `risk = severity×25 + exploit×25 + exposure×50`(F5-1, D13). |
| ★ 버킷 | 이번 주 / 다음 스프린트 / 지켜보기 3칸 분류입니다. | NOW ≥ 60, NEXT 30~60(또는 ≥ 60인데 수정 버전 없음), MONITOR < 30(F5, D7). |
| 경보 피로 | 경고가 너무 많아 전부 무시하게 되는 현상입니다. | 이 프로젝트가 푸는 문제입니다. 규칙 단계 노이즈 감소 92.9%는 정답률이 아니라 분포입니다. |
| ★ 하이브리드 판단과 ±1 제약 | 숫자는 규칙, 코드 맥락은 AI가 맡습니다. AI는 버킷을 한 단계만 바꿀 수 있고 사유가 필수입니다. | D5, D6. 위반하면 규칙 결과로 fallback합니다. |
| 하향 안전장치 | AI가 위험 항목을 낮추는 사고를 코드로 막는 규칙입니다. | KEV 하향 금지, EPSS 백분위 0.9 이상이면서 runtime import가 있거나 규칙 버킷이 NOW이면 `needs_review`(F6-9, D26, D37). |
| golden set, 일치율 | 사람이 매긴 정답 모음과, 시스템이 그 정답과 같은 비율입니다. | CVSS 정렬, 규칙, 규칙+에이전트를 비교합니다. 목표 80% 이상, 미측정입니다. |
| ★ NOW 누락 | 정답이 NOW인데 최종이 MONITOR인 건수입니다. | 목표 0건, 미측정입니다. 놓침이 과잉 경고보다 비싸서 따로 봅니다. |

**예상 질문:** 정확도는 몇 %인가요?
**답:** 목표는 일치율 80% 이상이고 아직 라벨링 전이라 미측정입니다. NOW 누락을 별도로 보겠습니다.

## 3. AI 에이전트

| 키워드 | 뜻 | 우리 프로젝트에서 |
|---|---|---|
| tool use | LLM이 함수 호출을 요청하고 우리 코드가 대신 실행하는 방식입니다. | `get_finding`, `search_usages`, `read_file`, `get_advisory`. 읽기 전용, 항목당 최대 6회입니다. |
| 스키마 강제 | LLM 출력을 정해진 JSON으로만 받아 Pydantic으로 검사합니다. API 응답을 TypeScript 타입으로 좁히는 것과 비슷합니다. | `AgentVerdict`에는 점수 필드가 없습니다. 실패하면 1회 재시도 후 규칙 결과를 씁니다(F6-5). |
| ★ 프롬프트 인젝션 | 코드나 문서에 숨긴 문장으로 LLM을 조종하는 공격입니다. | LLM 문자열을 실행하지 않고 코드가 명령을 조립합니다(D15, F8-11, F6-8). |
| 자리표시자 근거 | AI가 `{cvss}`로 쓰면 코드가 실제 값을 채웁니다. 템플릿 치환과 같습니다. | D18, F6-3. 다른 수치는 테스트가 잡습니다. |
| human-in-the-loop | 최종 실행 전에 사람이 확인하는 단계입니다. | 원본 반영, 커밋, PR은 사람 승인 뒤 별도 경로입니다. |

**예상 질문:** AI가 악성 명령을 실행하게 속일 수 있지 않나요?
**답:** AI는 버전만 제안하고, 실행 명령은 코드가 검증된 값으로 조립하며 에이전트 도구는 전부 읽기 전용입니다.

## 4. 샌드박스 검증

| 키워드 | 뜻 | 우리 프로젝트에서 |
|---|---|---|
| ★ 일회용 컨테이너 | 한 번 쓰고 버리는 격리된 Docker 실행 환경입니다. | NOW 조치안만 검증합니다(F8-1). 원본은 읽기 전용, 복사본만 수정합니다(F8-2). |
| `--ignore-scripts` | npm 설치 때 패키지 스크립트 자동 실행을 막습니다. | 설치 스크립트 공격을 차단합니다(F8-7). 그래서 `prisma generate`를 따로 실행합니다. |
| cap-drop | 컨테이너의 리눅스 권한을 빼는 Docker 옵션입니다. | PoC에 `--cap-drop ALL`과 메모리, CPU, PID 제한이 있습니다. `--read-only`는 미적용입니다. |
| egress 제한 | 컨테이너에서 밖으로 나가는 통신을 제한합니다. | install만 네트워크 허용, build와 test는 `--network none`(F8-7). 레지스트리 전용 프록시는 P2입니다. |
| ★ 기준선 비교 | 조치 전 결과와 조치 후 결과를 비교합니다. | 회귀만 실패로 판정합니다(D16, D28). 조치 전 실패 7건 때문에 테스트 이름 단위로 비교합니다. |
| overrides | 간접 의존성 버전을 고정하는 npm 기능입니다. | `override_transitive`에 쓰입니다. 옛 복사본이 남아 lockfile 항목을 제거합니다(F8-13). |
| lockfile | 설치된 정확한 버전과 구조를 기록한 파일입니다. | dev/prod, direct 판단 근거입니다. 조치 전 `npm ci`, 조치 후 `npm install --ignore-scripts`를 씁니다. |
| ★ 검증 강도와 verdict | verdict는 `verified` / `failed` / `inconclusive`, 검증 강도는 실제 실행된 테스트 수입니다. | D30, F8-15. NOW 패키지 30개 중 verified 20개, 그중 실제 테스트 확인은 2개입니다. |

**예상 질문:** 검증됐다는 게 정말 안전하다는 뜻인가요?
**답:** 아닙니다. verified 20개 중 실제 테스트 확인은 2개라서, 판정과 별도로 테스트 수를 표시하고 한계를 숨기지 않습니다.

## 5. 운영 설계 (구현 없음, 설계와 PoC)

| 키워드 | 뜻 | 우리 프로젝트에서 |
|---|---|---|
| 온프레미스 | 클라우드가 아니라 사내망에 직접 설치해 운영하는 방식입니다. | 설계로만 제시합니다(D10). |
| 정적 서빙 | 미리 빌드한 HTML, JS, CSS를 그대로 내려 주는 방식입니다. | FastAPI가 React 빌드 결과를 서빙합니다(D31). |
| SSE | 서버가 연결을 열어 두고 한 방향으로 메시지를 보내는 방식입니다. | 분석 진행 로그. 리플레이는 `events.jsonl`을 재생합니다(N7). |
| 작업 큐, 워커 | 큐는 할 일 목록, 워커는 꺼내서 실행하는 별도 프로세스입니다. | D32. `poc/queue_poc.py`의 `jobs` 테이블로 시험했습니다. |
| `FOR UPDATE SKIP LOCKED` | 이미 잠긴 행을 기다리지 않고 건너뜁니다. 워커들이 같은 일을 집지 않으면서 막히지도 않습니다. | CLAIM 쿼리에서 사용. 2만 건 3회 실행에서 같은 시도의 중복 획득 0건입니다. |
| lease | 일을 집을 때 거는 만료 시간입니다. 지나면 다른 워커가 집을 수 있습니다. | 워커를 강제 종료해도 그 작업은 재처리되어 완료됐습니다. |
| fencing | 만료 후 뒤늦게 온 옛 워커의 완료 보고를 거절합니다. | FINISH 조건으로 구현. 멈췄다 재개한 워커의 완료가 거절됐습니다. |
| at-least-once, 멱등성 | 최소 한 번 실행(두 번일 수 있음)과, 여러 번 해도 결과가 같은 성질입니다. | 작업은 재실행될 수 있습니다. 일회용 컨테이너라 재실행해도 안전하다는 것은 설계 해석입니다. |
| JSONB | PostgreSQL의 검색 가능한 JSON 컬럼 타입입니다. | 결과 문서 저장 후보입니다. D32에는 아직 적혀 있지 않습니다. |
| 처리량 꺾임 | 동시 실행을 늘려도 자원 한계로 처리량이 늘지 않는 지점입니다. | 이 PC에서는 동시 4개에서 최고(1개 대비 약 2.2배)였고 8개부터 줄었습니다(D33). 절대값은 환경마다 다릅니다. |
| 단일 장애점 | 하나가 죽으면 전체가 멈추는 구성 요소입니다. | 운영 설계에서는 PostgreSQL이 해당합니다. 이번 PoC는 DB 장애를 시험하지 않았습니다. |

**예상 질문:** 여러 팀이 동시에 요청하면 어떻게 확장하나요?
**답:** 프로토타입은 파일 저장소이고, 확장은 PostgreSQL 작업 큐와 워커 분리로 설계했습니다. 구현은 아직 없습니다. PoC에서 샌드박스는 동시 4개가 최고였고 워커 장애 시 작업 유실은 없었으니, 서버를 늘려 확장합니다. LLM 병목은 아직 측정하지 않았습니다.

## 발표 전 주의

- "47 → 3" 같은 숫자는 가정입니다. 실측은 규칙 단계 기준 NOW 41건 / 581건(7.1%)입니다.
- AI 성능과 일치율은 아직 말할 수치가 없습니다.
- 기존 도구 비교표는 공식 문서로 재검증되지 않았습니다.
