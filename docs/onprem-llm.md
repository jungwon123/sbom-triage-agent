# 사내망 LLM 구성 (설계와 측정)

작성: 2026-11-18. 결정 번호는 `HANDOFF.md`의 D34, D35.

## 1. 구성

| 역할 | 어디서 도는가 | 보는 데이터 | 설정 |
|---|---|---|---|
| 규칙 점수 | 사내망 | 전부 | 항상 켜짐 |
| 코드 판독 모델 | 사내망 (Ollama, vLLM 등 OpenAI 호환 서버) | 소스코드, 어드바이저리 | `LLM_CODE_PROVIDER=local`, `LOCAL_LLM_MODEL` |
| 작성 모델 | 외부 API 또는 사내망 | CVE ID, 패키지, 버전, 점수, 판독 결과 | `LLM_PROVIDER` |
| 알림 | Slack 또는 사내 메신저 웹훅 | 패키지, CVE ID, 등급, 검증 판정 | `SLACK_WEBHOOK_URL` |

구성은 세 가지로 쓸 수 있다.

1. **외부 전송 없음**: `LLM_PROVIDER=none`, `LLM_CODE_PROVIDER=local`. 사내 모델이 코드 사용 여부만 판정하고 등급은 규칙 결과를 쓴다.
2. **분리**: `LLM_PROVIDER=anthropic`(또는 openai), `LLM_CODE_PROVIDER=local`. 코드는 사내 모델만 읽고 외부 모델은 사실 값으로 근거와 조치안을 쓴다.
3. **전부 사내**: `LLM_PROVIDER=local`. 한 모델이 판독과 작성을 모두 한다.

외부 모델에 가지 않는 것: 소스코드, 파일 이름, 도구 호출 결과. `tests/test_two_stage.py`가 확인한다.
파일 이름도 보내지 않는 이유는 원문이 아니어도 내부 구조를 드러내는 파생 정보이기 때문이다(참고 1의 "임베딩도 보호 대상"과 같은 생각).

## 2. 작은 모델을 써도 안전한 이유

사내에서 돌릴 수 있는 모델은 외부 모델보다 약하다. 그 약점이 사고로 이어지지 않게 코드가 막는다.

- 점수는 규칙이 계산하고 모델은 등급을 한 단계만 바꿀 수 있다.
- 형식이나 계약을 어긴 답은 한 번 다시 묻고, 그래도 어기면 규칙 결과를 쓴다.
- 코드 판독 모델이 파일을 하나도 열어 보지 않고 답하면 그 답을 버린다.
- KEV 항목은 등급을 낮출 수 없고, 샌드박스 명령은 코드가 만든다.

## 3. 로컬 모델 측정 (2026-11-18)

환경: Apple M3 Pro, 메모리 18GB, Ollama 0.40.16, `qwen2.5:7b`(4.7GB). 대상: 데모 레포 실행의 상위 6건. 정답 라벨이 없어 정확도는 측정하지 못했다.

| 구성 | 유효한 답 | 규칙 대체 | 도구 호출(오류) | 계약 위반 | 걸린 시간 |
|---|---|---|---|---|---|
| 코드 판독만 (`local_reader`) | 6 / 6 | 0 | 21 (3) | 1 | 168초 |
| 판독과 작성 모두 (`local`) | 5 / 6 | 1 | 16 (0) | 5 | 253초 |

관찰한 것:

- **도구 호출은 된다.** 어드바이저리를 읽고, 사용 위치를 검색하고, 파일을 열었다. `body-parser`에서는 `bodyParser.urlencoded` 호출을 찾아 "취약한 코드를 사용함"으로 판정했다.
- **JSON을 강제하면 도구를 부르지 않는다.** 처음에는 출력 형식을 스키마로 강제했더니 도구 호출이 0회였고 규칙 결과를 그대로 따라 말했다. 도구가 있는 단계에서는 형식 강제를 끄고 코드에서 검증하도록 바꿨다.
- **작성은 약하다.** 근거 문장에 숫자를 직접 쓰거나 영어로 쓰는 위반이 많았다. 한 번 다시 물으면 대부분 고쳐졌다.
- **느리다.** 항목당 30~40초. 후보가 수십 건이면 수십 분이 걸리므로 운영에서는 GPU 서버와 vLLM이 필요하다.
- 같은 취약점(`body-parser` 1.20.1과 1.20.2)에 다른 판정이 나온 경우가 있었다. 판정의 일관성은 따로 측정해야 한다.

### 네 구성 비교 (같은 6건)

| 구성 | 유효한 답 | 도구 호출(오류) | 계약 위반 | 등급 조정 | 걸린 시간 | 토큰(입력 / 출력) |
|---|---|---|---|---|---|---|
| API 단독 (Claude Fable 5.2) | 6 / 6 | 23 (1) | 0 | 3건 | 33초 | 50,186 / 7,933 |
| 분리 (판독 qwen2.5:7b, 작성 Fable 5.2) | 6 / 6 | 20 (2) | 1 | 3건 | 133초 | 42,551 / 8,247 |
| 로컬 단독 (qwen2.5:7b) | 5 / 6 | 16 (0) | 5 | 3건 | 253초 | 로컬 |
| 로컬 판독만 | 6 / 6 | 21 (3) | 1 | 0건 | 168초 | 로컬 |

코드 사용 여부 판정을 항목별로 보면 다음과 같다. 정답 라벨이 없어서 어느 쪽이 맞는지는 확정하지 못했다.

| 항목 | API 단독 | 분리 (로컬 판독) | 같은가 |
|---|---|---|---|
| body-parser 1.20.2, CVE-2026-111181 | 사용함 | 사용함 | 같음 |
| body-parser 1.20.2, CVE-2024-45590 | 사용함 | import만 | 다름 |
| express 4.18.2, CVE-2024-29041 | import만 | 사용함 | 다름 |
| body-parser 1.20.1, CVE-2024-45590 | 사용함 | import만 | 다름 |
| form-data 4.0.0, CVE-2025-7783 | 사용 안 함 | import만 | 다름 (등급 결론은 같음) |
| path-to-regexp 0.1.7, CVE-2024-45296 | 판단 못 함 | 판단 못 함 | 같음 |

- 6건 중 4건에서 판정이 달랐다. API 모델은 근거로 구체적인 코드(`bodyParser.urlencoded({ extended: true })`가 전역 미들웨어로 등록됨, `res.redirect()` 호출이 없음)를 들었고, 로컬 모델은 같은 취약점을 실행할 때마다 다르게 판정했다.
- 분리 구성은 코드가 밖으로 나가지 않는 대신 로컬 모델의 판독 오류를 그대로 물려받는다. express 항목은 로컬 판독 때문에 NOW로 올라갔다.
- API 단독에서 form-data(CVSS 9.5)는 NOW에서 NEXT로 내려갔다. 이 패키지를 끌어오는 axios가 테스트 코드에서만 쓰이기 때문이다. 지원서에 쓴 사례를 AI가 실제로 찾아낸 것이다.
- 비용: API 단독은 항목당 입력 약 8,400토큰, 출력 약 1,300토큰이었다.

결론: 지금 크기의 로컬 모델(7B)은 코드 판독을 맡기기에 부족하다. 사내 반입을 전제로 하면 더 큰 모델(14B~32B)과 GPU 서버로 다시 측정해야 하고, 그 전까지 분리 구성은 "코드를 내보낼 수 없는 레포"에만 쓰는 선택지로 둔다.

아직 하지 않은 것: 정답 대비 정확도(라벨 0건), 더 큰 로컬 모델 비교, 87건 전체 실행(6건만 실행).

## 4. 폐쇄망 반입 설계 (구현하지 않음)

참고 2의 운영 원칙에 우리 구성을 대응시켰다.

| 원칙 | 우리 구성에서 필요한 것 | 현재 |
|---|---|---|
| 외부 통신 없는 배포 | 컨테이너 이미지(`node:20-slim`), Python과 npm 패키지, Syft, 모델 가중치를 외부에서 검증한 뒤 반입. 사내 레지스트리와 npm 미러 사용 | 화면 글꼴은 번들에 포함. 나머지는 설계 |
| 취약점 데이터 | OSV, EPSS, KEV를 주기적으로 받아 사내에 미러링 | 응답 캐시와 `DEMO_MODE=replay`로 오프라인 동작은 확인 |
| 최소 권한 | 에이전트 도구는 읽기 전용, 레포 밖 접근 차단. 운영에서는 전용 서비스 계정과 읽기 전용 저장소 권한 | 도구 제한은 구현과 테스트 완료 |
| 비밀값 관리 | `.env` 대신 사내 비밀 저장소에서 주입하고 주기적으로 교체 | `.env`만 사용 |
| 사람 승인 | 원본 반영은 담당자 승인 뒤에만. 알림에서 대시보드로 연결 | 알림과 화면은 구현. 승인 뒤 반영은 설계 |
| 감사 기록 | 단계별 이벤트와 모델의 도구 호출 기록 보관 | `events.jsonl`, `agent_log.jsonl` |
| 모델 검증 | 도구 선택, JSON 형식 준수, 인자 정확성을 실제 업무 데이터로 측정 | `triage compare`가 도구 호출 수, 오류, 계약 위반을 집계 |
