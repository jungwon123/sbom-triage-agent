# 라벨링 기준

`fixtures/golden-sheet.csv`의 `label` 칸에 각 항목의 정답 버킷을 적는다. 이 값이 평가의 정답이 된다.

## 버킷 뜻

| 버킷 | 질문 | 예 |
|---|---|---|
| NOW | 이번 주 일정을 바꿔서라도 고칠 것인가? | 외부 입력이 닿는 운영 코드에서 쓰고, 악용 가능성이 높다 |
| NEXT | 다음 스프린트에 넣을 것인가? | 위험은 있지만 조건이 까다롭거나 간접 경로다 |
| MONITOR | 지금은 일을 잡지 않고 지켜볼 것인가? | 개발 도구 전용이거나 운영 코드에서 쓰지 않는다 |

## 판단 방법

1. 이 서비스의 담당자라고 가정한다.
2. 시트의 정보와 `link`의 어드바이저리를 읽는다.
3. 필요하면 `fixtures/demo-repo`, `fixtures/eval/` 코드를 직접 연다.
4. 고치기 어렵다고 위험을 낮추지 않는다. 다만 수정 버전이 없으면 NEXT까지로 본다.

`confidence`는 판단 확신을 상, 중, 하로 적고, 판단이 갈리면 `memo`에 이유를 짧게 남긴다.

## 지킬 것

- 라벨을 마칠 때까지 `out/poc/`, `docs/poc-results.md`의 점수와 버킷을 보지 않는다.
- 항목은 사람이 판단한다. AI에게 라벨을 묻지 않는다. 정답을 AI가 만들면 평가가 무의미해진다.
- 한 번 적은 뒤 결과를 보고 바꾸지 않는다. 바꾸려면 `memo`에 이유를 남긴다.
- 건당 2~3분이면 충분하다. 20건 기준 약 1시간이다.
